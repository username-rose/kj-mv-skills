# 音频同步与 LEAD 标定

## 零、核心认知：公式对 ≠ 观感对

```ts
绝对帧 = Math.round((lrc秒 - CONFIG.audioFromSec) * CONFIG.fps)
```

这个公式算出来的位置是**数学正确**的。但真实观感还可能偏，原因只有三种：LRC 本身偏、播放环境有延迟、人眼需要提前量。

**所以不要一上来就调 `LEAD`。** 按下面的判定顺序走，能省掉一半的返工。

---

## 一、感觉字幕晚了，按这个顺序排查

| 顺序 | 查什么 | 怎么查 | 结论 |
|---|---|---|---|
| 1 | `audioFromSec` 算错没 | 第一句的绝对帧应 ≤ 2 秒（60 帧） | 超了 → 回去重算 offset（见 `rules.md` §4.2） |
| 2 | LRC 有没有偏移 | 拿第一句的时间戳，对着原曲听一遍 | 整行都偏 → 是 LRC 本身的问题，改 LRC 不改代码 |
| 3 | 播放环境延迟 | 同一文件换一个播放器对比 | 只在某个播放器偏 → 是环境，别改代码 |
| 4 | 渲染出的音轨有没有错位 | 互相关校验（见第三节） | `lag ≠ 0` → 是渲染问题 |
| 5 | 以上都正常 | 才调 `LEAD` | 按第四节的标定法，每次 ±3~4 帧 |

**跳过前四步直接调 LEAD，是把环境问题固化进代码**——换台机器就全错。

---

## 二、`LEAD` 是什么

字幕比人声**提前**出现多少帧。默认 `4`（30fps 下约 133ms）。

提前是对的——人对"字幕先出、声音后到"的容忍度，比对"声音先出、字幕后到"高得多。但提前太多（>250ms）会明显觉得字幕抢拍。

**铁律：`LEAD` 只能全局调一个常量，不许逐字改 `hits` 数组。**

逐字改会让你陷入"这句好了那句又坏"，永远调不完。全局一个值，全片统一偏早或偏晚，观感可接受。

---

## 三、互相关校验（客观验证）

渲完一条后，验证输出音轨与源音频是否对齐：

```bash
# 1. 抽出两条音轨
ffmpeg -i out.mp4 -vn -ac 1 -ar 8000 -f wav out.wav
ffmpeg -ss <audioFromSec> -i song.mp3 -t <duration> -vn -ac 1 -ar 8000 -f wav src.wav

# 2. 用 python 算互相关找峰值偏移
python -c "
import wave, numpy as np
def rd(p):
    w=wave.open(p); n=w.getnframes()
    return np.frombuffer(w.readframes(n),dtype=np.int16).astype(float)
a,b=rd('out.wav'),rd('src.wav')
n=min(len(a),len(b)); a,b=a[:n],b[:n]
c=np.correlate(a-a.mean(),b-b.mean(),'full')
lag=np.argmax(c)-(n-1)
print('lag(samples)=',lag,'-> lag(ms)=',lag/8)
"
```

- `lag ≈ 0ms` → 渲染对齐正确，问题在别处（回去看第二节前四步）
- `lag` 明显非 0 → 渲染链路有问题，先修这个再谈 LEAD

期望值：**|lag| ≤ 5ms**。

## 四、`LEAD` 标定流程

1. 从 `4` 开始渲一小段（就选第一句，不用渲全片）
2. 在**真实播放器**里看（不要在编辑器预览里判断）
3. 偏晚 → `+3` 或 `+4`；偏早 → `-3` 或 `-4`
4. 重复 2–3 轮，直到"看着刚好"
5. **记下来**：在第几帧、为什么、最后是多少

```ts
// config.ts
lead: 4,   // 标定于 2026-10-24，本机 + Chrome，最终 7
```

**不要把某台机器标定出来的值当默认值写进 skill。** 换机器、换播放器、换歌都可能不同。

## 五、逐字时间：均分 vs `hits`

`hits` 是逐字实际演唱时间数组（秒，绝对音频轴）。

| 情况 | 用什么 |
|---|---|
| 节奏均匀、一字一拍 | 行内均分（兜底） |
| 句中有明显停顿 | **必须给 `hits`** |
| 有拖长音（一个字唱两拍） | **必须给 `hits`** |
| 关键词组要整组同时亮 | 给 `hotAt` 定点帧 |

均分公式：`hitAt = start + (i * (end - start) / N) - lead`

**均分只当兜底。** 长句用均分会漂——真实成片踩过：按句长均分后，后半句字幕比人声晚了小半句。

## 六、片尾死线（和同步强相关）

```ts
// 死命令：唱完再黑
const FADE_FROM = LINES[LINES.length - 1].end;
```

**不是** `durationInFrames - N`。写成后者时最后一句会被渐黑吃掉半个字——这个坑真实发生过，用户直接退回重做。

- 渐黑 42 帧
- 歌词框在最后一句 `end` 后 10 帧内淡出
- 片名/署名在渐黑完成后再 +8 帧
